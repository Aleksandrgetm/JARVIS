# JARVIS — Voice Input + Voice Output

Локальный CLI-ассистент для macOS. **Версия 1.0.0, этап 3.**
Требуется Python 3.9 или новее. Только стандартная библиотека Python;
Для CLI установка зависимостей не нужна. Для voice mode требуются системные
Xcode Command Line Tools (Swift); Python-пакеты и ML-модели не устанавливаются.

## TEXT MODE

Из каталога проекта:

```bash
python3 main.py
# Явный выбор того же CLI:
python3 main.py --text
```

```text
JARVIS
System online.

jarvis > status
JARVIS is online.
jarvis > version
JARVIS 1.0.0
jarvis > open app Visual Studio Code
Opening Visual Studio Code.
jarvis > volume 30
Set volume to 30%? [y/N] n
Cancelled.
jarvis > exit
System offline.
```

## Команды

| Команда | Назначение | Уровень |
| --- | --- | --- |
| help | Список команд по группам SYSTEM / MACOS | SAFE |
| status | Состояние ассистента | SAFE |
| version | Версия приложения | SAFE |
| clear | Очистка терминала ANSI-последовательностью | SAFE |
| exit | Завершение приложения | SAFE |
| open app <name> | Запуск приложения через open -a | SAFE |
| open url <url> | Открытие HTTP(S) URL в браузере по умолчанию | SAFE |
| open folder <path> | Открытие существующей директории в Finder | SAFE |
| system info | Версия macOS, архитектура, hostname, версия Python | SAFE |
| volume <0-100> | Изменение выходной громкости | CONFIRM |
| mute | Выключение звука | CONFIRM |
| unmute | Включение звука | CONFIRM |
| screenshot | Скриншот основного экрана в PNG | CONFIRM |

Ключевые слова команд нечувствительны к регистру. Регистр аргументов сохраняется.
Имена с пробелами принимаются с кавычками и без них:

```text
open app Visual Studio Code
open app "Visual Studio Code"
open folder ~/Desktop/Projects/JARVIS
open folder "/absolute/path/Folder With Spaces"
open url youtube.com
```

Парсер использует `shlex` только для разбора текста, без исполнения shell.
Несколько не заключённых в кавычки пробелов между словами нормализуются;
для сохранения повторяющихся пробелов внутри имени используйте кавычки.
URL без схемы получает `https://`; допускаются только `http` и `https`.
Для hostname с портом явно укажите схему, например `http://localhost:8080`.
URL с логином/паролем, некорректным hostname/портом, пробелами или другой схемой отклоняются.

Псевдонимы директорий:

- Desktop → `~/Desktop`
- Downloads → `~/Downloads`
- Documents → `~/Documents`
- Projects → `~/Desktop/Projects`

Поддерживаются `~`, абсолютные и относительные пути. Относительные пути
разрешаются от текущего рабочего каталога; директория должна существовать.

## Разрешения и безопасность

PermissionManager сохраняет три уровня:

- **SAFE**: выполняется после проверки аргументов.
- **CONFIRM**: CLI спрашивает подтверждение; только `y` и `yes`
  (без учёта регистра и пробелов по краям) разрешают действие. Остальное — отмена.
- **DANGEROUS**: всегда заблокирован; таких команд нет.

Валидация выполняется до подтверждения. Без подтверждения Router не запускает
CONFIRM-обработчик. Внутренний параметр `confirmed=True` предназначен для
доверенного вызывающего кода, не предоставляется как CLI-аргумент.

Все нативные процессы запускаются через `subprocess.run` с массивами аргументов,
`shell=False`, абсолютными путями к утилитам и тайм-аутом 15 секунд.
Команд `run`, `exec`, `shell`, `terminal` нет. Имя приложения передаётся одним
аргументом, пути и параметры запуска приложения не поддерживаются.
Громкость принимает только целое число 0–100; AppleScript состоит из фиксированной
команды и проверенного числа либо фиксированного boolean. Произвольный AppleScript
или shell-код пользователя не исполняется.

Пустой ввод пропускается. Неизвестные команды и неправильные аргументы дают
понятную ошибку. Ошибки нативных утилит и тайм-ауты обрабатываются; CLI продолжает
работу. Ctrl+C и EOF (Ctrl+D), в том числе во время подтверждения, завершают CLI.
`clear` ничего не выводит при перенаправлении stdout.

## Скриншоты и логи

Скриншоты создаются в `data/screenshots/` относительно проекта:

```text
screenshot_YYYY-MM-DD_HH-MM-SS.png
```

Используется `/usr/sbin/screencapture -x -m -t png`: основной экран, без звука.
Проверяются успешный код завершения и существование непустого файла. Уже занятое
имя не перезаписывается: повторите команду через секунду. Неудачная попытка
очищает зарезервированный/частичный файл.

macOS может потребовать разрешение Screen Recording для приложения, из которого
запущен Python (например Terminal). JARVIS не выдаёт это разрешение автоматически.
При отказе выводится ошибка. Каталог данных должен быть доступен для записи.

Логи: `data/logs/jarvis.log`, UTF-8, ротация при 1 000 000 байт,
до трёх архивов. Записываются тип действия и результат, отмены, ошибки;
для скриншота — только имя файла. URL, query-параметры, пути папок, имена
приложений, hostname и сырой ответ подтверждения в журнал не записываются.
Ожидаемые ошибки процессов не включают stdout/stderr. Для неожиданных ошибок
обработчиков сохраняется traceback, поэтому сообщения будущих обработчиков
не должны содержать секреты. Скриншоты и логи исключены из Git.

## Архитектура

```text
main.py                 — выбор --text / --voice и запуск
core/
  bootstrap.py          — один реестр Router/Actions для обоих интерфейсов
  assistant.py          — CLI, подтверждение, обработка ошибок
  router.py             — реестр, разбор команды, валидация, проверка разрешений
  commands.py           — команды этапа 1 и help из реестра
  permissions.py        — политика SAFE / CONFIRM / DANGEROUS
  config.py             — версия и пути данных
  logger.py             — файловое логирование с ротацией
actions/
  commands.py           — регистрация действий и их метаданных
  macos.py              — общий запуск нативных процессов, ActionError
  apps.py               — запуск приложения
  browser.py            — проверка и открытие URL
  filesystem.py         — разрешение и открытие директорий
  system.py             — громкость, mute, screenshot, system info
voice/                  — голосовой интерфейс (структура ниже)
brain/, memory/         — пакеты для будущих этапов
```

Router выбирает наиболее длинное совпадающее имя команды и передаёт остаток
как один аргумент. Command содержит обработчик, валидатор, уровень разрешений,
текст подтверждения и метаданные help. Команды без аргументов этапа 1 сохраняют
прежнюю сигнатуру. CommandResult отделяет результат действия от вывода CLI.
Assistant по-прежнему поддерживает подмену Router и функций ввода/вывода в тестах.

## Тесты

```bash

```

Тесты этапа 1 сохранены с обновлёнными ожиданиями версии и допустимых составных
имён команд. Тесты этапа 2 проверяют parsing, приложения, URL, директории,

заменены mocks: тесты не меняют громкость, не открывают окна и не снимают экран.

## VOICE MODE

```bash
python3 main.py --voice
```

Обычный запуск и `--text` не импортируют голосовые адаптеры, не собирают
Swift-модуль, не запрашивают разрешения и не включают микрофон.

### Зависимости и STT

Используются системные **Apple Speech (SFSpeechRecognizer)** и **AVFoundation
(AVAudioEngine)**. Небольшой Swift-модуль передаёт аудиобуферы из микрофона
непосредственно распознавателю в памяти. Python управляет процессом и получает
один JSON-результат с финальным текстом. Обработка намерений и действий остаётся
в существующем Python-проекте.

Этот подход не требует PyObjC, Whisper, внешней ML-инфраструктуры или API-ключей.
Для сборки нужен Swift из Xcode Command Line Tools. Проверка:

```bash
xcrun --find swiftc
```

Если инструменты отсутствуют, установите их самостоятельно:

```bash
xcode-select --install
```

Первый `--voice` собирает и локально подписывает исполняемый модуль в
`data/voice/`. Там находятся только бинарник, хеш исходников и кэш компилятора,
аудиофайлов нет. Повторный запуск использует кэш; изменение Swift-исходников
вызывает пересборку. Каталог исключён из Git. Сборка не выполняется в text mode.

### Интернет и приватность

По умолчанию язык — **ru-RU**, режим — **только на устройстве**:
`requiresOnDeviceRecognition = true`. Если Apple Speech не поддерживает локальное
распознавание выбранного языка или нужные ресурсы недоступны, JARVIS сообщает
об ошибке. Автоматического перехода к серверному распознаванию нет.

Для явного разрешения обработки на серверах Apple:

```bash
python3 main.py --voice --voice-allow-network
```

В этом режиме **аудио может передаваться Apple через интернет**; сетевые ошибки
обрабатываются. Это не OpenAI API. Флаг действует только на текущий запуск
`--voice`, режим отображается в Terminal. Сетевой режим может потребоваться,
если локальная поддержка языка недоступна. Системным речевым ресурсам также
может потребоваться первоначальная загрузка средствами macOS.

Поддержка on-device зависит от языка и системных ресурсов: см.
[Apple supportsOnDeviceRecognition](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition).
Реализация использует схему потоковых аудиобуферов из
[Apple Recognizing speech in live audio](https://developer.apple.com/documentation/speech/recognizing-speech-in-live-audio).

По умолчанию JARVIS:

- не сохраняет сырое аудио и историю записей;
- выводит распознанный текст только в текущий Terminal, без записи транскриптов в лог;
- не слушает вне активного `--voice`;
- закрывает микрофон после каждой фразы, до выполнения Action и ответа TTS;
- не запускает daemon, фоновый сервис или настоящий wake-word detector.

### Разрешения macOS

Запускайте из Terminal или используемого терминального приложения. При первом
запуске macOS может запросить **Speech Recognition** и **Microphone**. Включите
доступ для приложения, из которого запускается Python, в:

**System Settings → Privacy & Security → Microphone / Speech Recognition**.

В зависимости от среды запуска система может показывать имя Terminal,
терминального приложения или JARVIS Speech. Затем повторите `--voice`.
Наличие системного отказа сразу завершает сессию с инструкцией, без traceback.
JARVIS не меняет настройки разрешений и не пытается их обходить.
Доступ в песочнице Codex может отличаться от доступа при запуске из Terminal.

Если микрофон недоступен, проверьте устройство ввода в настройках Sound.
Если локальный распознаватель недоступен, проверьте системные речевые ресурсы;
не считайте, что смена языка гарантирует наличие локальной модели.

### TTS

Абстракция `TextToSpeech` имеет реализацию `MacOSTextToSpeech`: штатный
`/usr/bin/say`, русский голос **Milena**. Текст передаётся через stdin,
аргументы — массивом, без shell. Голос задаётся в `Config.tts_voice`.
Если выбранный голос недоступен, проверьте установленные голоса командой
`/usr/bin/say -v '?'` или добавьте русский голос средствами macOS.

Сначала ответ всегда печатается в Terminal, затем произносится.
При ошибке/тайм-ауте TTS текст остаётся доступен, сессия продолжается.
Длинный `help` и информация о системе выводятся полностью в Terminal,
а вслух произносится короткое уведомление. Завершение озвучивания предшествует
следующему открытию микрофона, чтобы JARVIS не распознавал собственный ответ.

### Голосовые подтверждения

SAFE выполняется сразу. Для CONFIRM Router вызывает голосовой callback:

```text
You: поставь громкость 30
JARVIS: Установить громкость 30 процентов?
Listening...
You: да
JARVIS: Команда выполнена.
```

Только отдельный точный ответ `да`, `подтверждаю`, `yes` разрешает действие
(регистр и завершающая пунктуация игнорируются). `нет`, `отмена`, `no`, тишина,
непонятный ответ, ошибка распознавания или тайм-аут не разрешают выполнение.
Ответ подтверждения не исполняется как новая команда и не переносится на
следующее действие. CLI-подтверждения `y`/`yes` остаются прежними.
DANGEROUS по-прежнему заблокирован.

### Сессия и обработка ошибок

Время разделено на независимые пределы в `core/config.py`:

| Параметр | Значение |
| --- | --- |
| Ожидание начала речи | 7 секунд после запуска audio engine |
| Максимум одной фразы | 15 секунд после обнаружения речи |
| Максимум ответа подтверждения | 5 секунд после обнаружения речи |
| Минимум после первого speech detection | 0,9 секунды |
| Тишина для окончания фразы | 1,8 секунды |
| Ожидание финального результата после закрытия микрофона | до 2,5 секунды |
| Пауза перед повторной попыткой | 0,4 секунды |

Начало и продолжение речи определяются по энергии аудиобуферов (порог −45 dBFS,
не менее 250 мс и трёх последовательных буферов для начала); распознанный текст служит дополнительным сигналом
для тихой речи. Отсутствие изменений partial-текста само по себе больше не
означает окончание фразы: пока приходит звук выше порога, запись продолжается.
При тишине в течение 7 секунд выводится `No speech detected.` и после cooldown
начинается следующая попытка. Таймеры используют монотонные часы.

Если audio engine не отдаёт буферы в течение 2 секунд, это отдельная ошибка
микрофона, а не «непонятная речь»: отсутствие буферов не засчитывается как тишина.
`kAFAssistantErrorDomain / 1110` обрабатывается как обычное отсутствие речи:
текущая попытка очищается, через 0,4 секунды снова `Listening...`. Другие
невосстанавливаемые ошибки движка завершают сессию с инструкцией запустить debug. Пустой или отсутствующий final не стирает последнюю непустую транскрипцию:
после 2,5 секунды ожидания она возвращается как fallback. Если непустого текста
не было вообще, возвращается восстанавливаемая ошибка с cooldown.

Нативный lifecycle регистрирует `recognitionTask` до старта микрофона. Буферы
в исходном формате inputNode передаются в тот же `SFSpeechAudioBufferRecognitionRequest`;
ручного resampling нет. Счётчик отражает вызовы `append`, а `appended_audio`
суммирует `frameLength / sampleRate`, поэтому число буферов не принимается за длительность.

При нормальном окончании фразы:

1. Синхронизированный gate запрещает новые append и дожидается текущего append.
2. Audio engine останавливается, tap удаляется.
3. `request.endAudio()` вызывается ровно один раз.
4. Ожидается непустой final result до 2,5 секунды. Он имеет приоритет;
   при пустом/отсутствующем final используется последняя непустая транскрипция.
5. Выбранный текст сохраняется в результирующий JSON до cleanup. При настоящем
   final вызова `cancel()` нет; при fallback оставшаяся задача отменяется только
   после сохранения результата. Поздние callbacks не могут его изменить.
6. Fallback проходит через тот же normalizer, Router и проверки разрешений.
   События `final result not emitted by Apple` и `using transcription fallback: ...`
   видны только в debug; аудио и история транскрипций не сохраняются.

Фоновый шум может удерживать запись до максимальной длительности; слишком
тихая речь может не пересечь энергетический порог. Для диагностики доступен
пиковый уровень и число полученных буферов. Это простой детектор активности
звука, а не отдельная ML-модель VAD.

Агрегированные уровни/длительности выводятся раз в секунду, не на каждый буфер.
Частота устройства и порядок final/stop могут отличаться. Ошибки Apple Speech
в debug включают `error domain=... code=... message=...` (краткое описание).
Debug не включает сетевой режим, не сохраняет raw audio и не пишет partial/final
в журнал. Распознанные фразы видны в Terminal; учитывайте это при пересылке
диагностического вывода. После успешного распознавания строка `You:` всегда
выводится до маршрутизации команды и ответа JARVIS.

Остановка: **Ctrl+C** или голосовая команда «выход».

```text
JARVIS voice session stopped.
```

При Ctrl+C дочерний процесс захвата завершается и освобождает микрофон.
Журнал содержит события `VOICE session_started`, `speech_recognized`,
`command_normalized`, `action_executed`, `recognition_failed`, `session_stopped`
и диагностические категории без текста речи и сырых ответов подтверждения.

### Структура voice

```text
voice/
├── __init__.py
├── errors.py               — ошибки адаптеров
├── listener.py             — жизненный цикл процесса захвата, тайм-ауты, очистка
├── native_bridge.py        — сборка/кэш нативного модуля
├── speech_to_text.py       — SpeechToText и адаптер Apple Speech
├── text_to_speech.py       — TextToSpeech и адаптер say
├── normalizer.py           — русская фраза → существующая CLI-команда
├── responses.py            — представление ответов и вопросов по-русски
├── voice_assistant.py      — voice session и вызовы общего Router
└── native/
    ├── Microphone.swift    — AVAudioEngine, только аудиобуферы в памяти
    ├── SpeechBridge.swift  — Apple Speech, финальный текст через JSON
    ├── SpeechTiming.swift  — независимые таймеры начала/длительности/тишины
    ├── RecognitionLifecycle.swift — append gate, endAudio/finalization/cleanup
    └── Info.plist          — идентификатор и описания macOS permissions
```

`core/bootstrap.py` собирает один и тот же набор команд для обоих интерфейсов.
Отдельной системы Actions для голоса нет. Язык STT задаётся в
`Config.voice_locale`; адаптер допускает другие локали (например en-US, lv-LV),
но наличие поддержки проверяет macOS. Сам normalizer на этом этапе русскоязычный.

### Проверки этапа 3 и ручной сценарий

```bash
python3 -m unittest discover -s tests -v
python3 main.py --text
python3 main.py --voice
```

Unit tests подменяют STT, TTS, процессы, действия и ввод/вывод: они не включают
микрофон, не произносят текст, не открывают приложения и не меняют громкость.
Проверяются normalizer, общий Router, подтверждения, отказ в разрешениях,
тайм-ауты, ошибки STT/TTS, завершение capture-процесса и отсутствие voice-старта
в текстовом режиме. Тесты этапов 1/2 сохранены; ожидаемая версия обновлена.

После выдачи разрешений произнесите по очереди:

1. После `Listening...` подождите 3–4 секунды, затем скажите «Джарвис, статус» — ответ «Система готова».
2. «Версия» — JARVIS 1.0.0.
3. «Открой Safari» — запуск существующего macOS Action.
4. «Открой загрузки» — открытие Downloads.
5. «Поставь громкость 30», затем «нет» — отмена без изменения громкости.
6. При желании повторите предыдущую команду и ответьте «да» — реальное изменение громкости.
7. «Сделай скриншот», затем «отмена» — файл не создаётся.
8. Неподдерживаемая фраза — «Команда не распознана».
9. Помолчите 7 секунд: `No speech detected.`, пауза 0,4 секунды, новая попытка.
10. Произнесите спокойно «Джарвис, открой Visual Studio Code»; проверьте полный `You:`.
11. «Выход» или Ctrl+C — завершение без traceback.

Если получите сообщение об отсутствии локального STT и согласны на обработку

### Известные ограничения

- Живое распознавание зависит от TCC-разрешений, микрофона и ресурсов Apple Speech.
  В среде Codex проверен отказ в доступе без падения; end-to-end распознавание
  реальной речи требует ручного запуска из Terminal с разрешениями.
- Поддерживается одна короткая команда за раз. Пауза посередине длинной фразы
  может закончить захват раньше; качество распознавания определяет Apple Speech.
- Поддержка русского локального STT есть на проверенном Mac вне песочницы,
  но не гарантируется на любой установке macOS.
- Milena должна быть доступна в macOS; при ошибке озвучивания работает текстовый ответ.
- Нет постоянного фонового прослушивания, свободного диалога, понимания произвольных
  намерений и полной поддержки английских/латышских команд.
